# משחק החיים

> מתוך חוברת C – שאלות לחזרה (עמ' 110).

## המשימה

קראו על משחק החיים בכתובת http://www.math.com/students/wonders/life/life.html
(או ב[ויקיפדיה](https://he.wikipedia.org/wiki/משחק_החיים)).

כתבו מימוש משלכם למשחק.

## החוקים

הלוח הוא רשת של תאים, כל תא חי או מת. לכל תא יש עד 8 שכנים (כולל באלכסון). בכל דור, **בבת אחת** לכל התאים:

- תא חי עם 2 או 3 שכנים חיים – נשאר חי. אחרת – מת.
- תא מת עם בדיוק 3 שכנים חיים – נולד (הופך לחי).

**מחוץ ללוח כל התאים מתים.** הלוח לא "מתגלגל" מצד לצד.

> שימו לב ל"בבת אחת": הדור הבא מחושב כולו מתוך הדור הנוכחי. אם תעדכנו תאים במקום, תאים שכבר עודכנו ישפיעו על השכנים שלהם – וזו טעות.

## הגדרות מדויקות (לצורך הבדיקה האוטומטית)

**הרצה**

```bash
./build/life <board-file> <generations>
```

התוכנית קוראת את הלוח מהקובץ, מריצה `<generations>` דורות, ומדפיסה ל-**stdout** את הלוח הסופי.

**פורמט הלוח (קלט ופלט – אותו פורמט)**

```
3 5
.....
.###.
.....
```

- שורה ראשונה: מספר השורות ומספר העמודות (שלמים חיוביים).
- אחריה בדיוק `rows` שורות, בכל אחת בדיוק `cols` תווים: `#` = חי, `.` = מת.
- הפלט באותו פורמט בדיוק: שורת הכותרת, ואחריה הלוח. כל שורה מסתיימת ב-`\n`.
  (כך אפשר להעביר פלט של הרצה אחת כקלט להרצה הבאה.)
- `generations` = `0` מדפיס את הלוח כמו שהוא.

**גבולות**

- גודל הלוח לא ידוע מראש – הקצאה דינמית. בבדיקות יש לוח של 200×300 עם 400 דורות, ומגבלת זמן של 10 שניות לבדיקה.

**שגיאות** – הודעה ל-**stderr** וקוד יציאה `1`, בלי פלט ל-stdout, בכל אחד מהמקרים:

- מספר ארגומנטים שגוי, או קובץ שלא ניתן לפתוח.
- `generations` שאינו מספר שלם אי-שלילי (`-1`, `abc`, `3x`).
- לוח לא תקין: אין שורת כותרת, גודל לא חיובי, תו שאינו `#` או `.`, שורה קצרה/ארוכה מדי, חסרות שורות.

הצלחה: קוד יציאה `0`. כל זיכרון שהוקצה משוחרר.

## רשות (לא נבדק אוטומטית)

הוסיפו אפשרות `--animate` שמציגה את הלוח בכל דור על המסך, עם השהיה קצרה בין דורות. בונוס: מצאו באינטרנט את ה-Gosper glider gun ותנו לו לרוץ.

## איך עובדים

```bash
make                       # קימפול ל-build/life
make test                  # כל הבדיקות
make asan                  # הבדיקות עם AddressSanitizer
tests/run_tests.sh 04_glider   # בדיקה אחת
./tests/grade.sh -v        # אותה בדיקה שרצה ב-GitHub: עבר / לא עבר, ומה נכשל
```

כל בדיקה היא תיקייה ב-`tests/cases` עם `board.txt`, `generations` ו-`expected.txt`. לוחות לא תקינים לבדיקת שגיאות נמצאים ב-`tests/bad`.
מותר לחלק את הקוד לכמה קבצי `.c` / `.h` בתוך `src/`.

## הגשה

- כל `git push` מריץ את הבדיקות אוטומטית. את התוצאה רואים בלשונית **Actions** של המאגר שלכם ← הריצה האחרונה ← **Summary**.
- ✅ ירוק = עבר: כל הבדיקות הצליחו. ❌ אדום = לא עבר: הרשימה ב-Summary מראה אילו בדיקות נכשלו.
- אחרי ההגשה תקבלו מהסגל הערה קצרה: מה לשפר, או "עבודה טובה!".
- נבדקת ההגשה האחרונה לפני הדדליין.
- **אסור לשנות** את התיקיות `tests/` ו-`.github/`. מאגר שבו הן שונו מסומן אצל הסגל.
